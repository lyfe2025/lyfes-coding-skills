# 前端验证

完成声明必须基于最新证据。按项目实际命令执行，不要假设存在固定测试框架。

## 1. 结构检查

- 使用语义化 HTML，heading 层级连续。
- 图片有合适 alt，表单控件有 label。
- Button 执行动作，Link 负责导航。
- 页面无意外横向滚动，长内容不会撑破布局。
- 固定导航、浮层和安全区不会遮挡内容。

## 2. 交互检查

- 使用键盘访问所有功能，Tab 顺序符合阅读顺序。
- `focus-visible` 清晰，Escape、Enter、Space 等行为符合组件语义。
- disabled、loading、error 和 success 状态不会误导。
- Hover 不是唯一提示，触控设备可以完成同样任务。
- 普通信息卡片没有 pointer cursor 或伪交互 hover。
- 快速重复点击、打开/关闭和提交不会产生竞态或视觉跳变。

## 3. 视觉检查

至少在以下宽度实际渲染：

- 375px
- 768px
- 1024px
- 1440px

检查：

- 内容优先级、行长、留白和视觉节奏
- 中文长标题、英文长单词与真实文案
- 图片裁切、缺图、加载失败和不同宽高比
- 0、1、少量和大量重复内容
- 下拉菜单、Dialog 等浮层是否被父容器裁切
- 项目支持主题切换时，分别验证 Light 和 Dark

## 4. 动效检查

- 无 `transition: all`，只动画必要属性。
- 快速反向或关闭时不会跳帧、从错误位置重启。
- 在 Reduced Motion 下完成同样任务。
- Hover 动效只在精细指针设备启用。
- 动画不延迟高频操作，不移动用户正在阅读或操作的数据。

## 5. 运行检查

1. 阅读项目文档和 package 配置，确定 lint、typecheck、test、build、dev 命令。
2. 运行与本次修改最相关的静态检查和测试。
3. 启动真实应用，实际访问受影响页面。
4. 检查浏览器控制台、网络失败、字体和图片加载。
5. 对视觉改动保留截图或清晰记录已验证的 viewport 与流程。

无法启动应用或缺少依赖时，明确说明：

- 已完成哪些静态验证
- 哪些运行时行为尚未验证
- 用户需要执行什么才能完成验证

只阅读源码、只生成代码或只通过 lint，都不能替代真实页面检查。
